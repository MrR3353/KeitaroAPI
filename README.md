# Keitaro Campaign Creator

Небольшой сервис на FastAPI + SQLAlchemy, который создаёт готовые к работе
кампании в Keitaro через Keitaro Admin API: по названию кампании, коду
страны и ID оффера Keitaro он создаёт кампанию с 2 потоками (flows):

1. **GEO-поток** (позиция 1) — ловит посетителей из указанной страны и
   редиректит их на Google (`GOOGLE_REDIRECT_URL`, по умолчанию
   `https://www.google.com`).
2. **Offer-поток** (позиция 2, без фильтров) — ловит всех остальных и
   направляет их напрямую на выбранный оффер Keitaro.

Также для кампании создаются отдельные **группа** и **источник трафика** в
Keitaro (названные так же, как кампания), и привязывается существующий
**домен** (см. раздел [Выбор домена](#выбор-домена) ниже).

Простой HTML/JS-фронтенд (`static/`) позволяет заполнить 3 поля и
посмотреть историю кампаний, созданных через этот инструмент.

## Требования

* Python 3.12+ (протестировано с `.venv` из этого репозитория)
* Работающий трекер Keitaro с доступом к Admin API (API-ключ)

## Установка

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp env.example .env
# отредактируйте .env: как минимум укажите KEITARO_BASE_URL и KEITARO_API_KEY
```

### Конфигурация (`.env`)

| Переменная                   | Обязательна | Описание                                                                                       |
|------------------------------|-------------|-------------------------------------------------------------------------------------------------|
| `KEITARO_BASE_URL`           | да          | Базовый URL вашего трекера, например `https://tracker.example.com` (без суффикса `/admin_api/v1`) |
| `KEITARO_API_KEY`            | да          | Admin API ключ (Keitaro → Settings → API)                                                       |
| `DATABASE_URL`               | нет         | SQLAlchemy-строка подключения к собственной БД приложения. По умолчанию: `sqlite:///./app.db`   |
| `KEITARO_DEFAULT_DOMAIN_ID`  | нет         | Жёстко задать домен для новых кампаний. Если пусто — берётся первый *активный* домен.            |
| `GOOGLE_REDIRECT_URL`        | нет         | Куда редиректит GEO-поток совпавший трафик. По умолчанию: `https://www.google.com`              |

## Миграции базы данных

Миграции управляются через Alembic и касаются только собственной служебной
таблицы приложения (`created_campaigns` — локальный журнал/история того,
что было создано в Keitaro). Сама Keitaro работает со своей базой данных
независимо от этого приложения.

```bash
# применить все миграции (создаст ./app.db при дефолтном sqlite)
alembic upgrade head

# после изменения app/models.py сгенерировать новую миграцию:
alembic revision --autogenerate -m "describe the change"
alembic upgrade head
```

## Запуск

```bash
uvicorn app.main:app --reload
```

Откройте http://127.0.0.1:8000/ для UI, либо используйте API напрямую:

```bash
curl -X POST http://127.0.0.1:8000/api/campaigns \
  -H "Content-Type: application/json" \
  -d '{"name": "Summer promo", "country_code": "US", "offer_id": 123}'
```

`GET /api/campaigns` возвращает историю кампаний, созданных через этот
инструмент. Интерактивная документация API доступна по адресу `/docs`.

## Редактор кампании

На странице истории у каждой кампании есть ссылка **Edit**, открывающая
`editor.html` — редактор потоков и офферов кампании.

* **Fetch streams from KT** — подтягивает потоки кампании из Keitaro и
  сверяет их офферы с локальным состоянием. Офферы, которые пропали из
  Keitaro (удалены вручную в трекере), не удаляются локально, а
  переводятся в статус `removed` (серые, с кнопкой **bring back**).
* **Добавление оффера** — поле поиска ищет офферы в Keitaro по ID или
  названию (запрос идёт через `GET /offers` с фильтрацией на бэкенде,
  так как отдельного search-эндпоинта в Admin API нет) и предлагает
  выпадающий список. После выбора оффер добавляется в поток локально в
  статусе `pending_add` (жёлтый) — веса потока пересчитываются, но
  изменение ещё не отправлено в Keitaro.
* **Push to KT** — отправляет текущий локальный состав и веса потока в
  Keitaro (`PUT /streams/{id}`). После этого `pending_add` → `active`,
  а `pending_remove` → `removed`.
* **Remove / Cancel / Bring back** — `Cancel` отменяет ещё не запушенное
  добавление (удаляет оффер локально без обращения к Keitaro); `Remove`
  помечает активный оффер на удаление (`pending_remove`, вес 0%, остальные
  веса пересчитываются) — реального удаления в Keitaro не происходит, пока
  не нажат `Push to KT`; `Bring back` возвращает оффер из `pending_remove`
  или `removed` обратно в `pending_add`.
* **Пин веса** — иконка 📌 у веса оффера фиксирует его текущее значение:
  при пересчёте веса остальных (активных/`pending_add`) офферов
  распределяются поровну на оставшуюся долю (100% минус сумма запиненных).

## Заметки по реализации

* **Выбор домена** — домены в Keitaro требуют реального владения DNS,
  поэтому инструмент не регистрирует новые домены. Используется либо
  домен, заданный через `KEITARO_DEFAULT_DOMAIN_ID`, либо автоматически
  выбирается первый `active`-домен из `GET /domains`.
* **Группа / источник трафика** — создаются заново для каждой кампании
  (тип `campaigns` для группы), с именем кампании, чтобы оставаться
  прослеживаемыми 1:1 с кампанией, которой принадлежат.
* **GEO-фильтр** — имя фильтра потока, используемого для сопоставления по
  стране (`country_code`, с фолбэком на `country`), определяется
  динамически через `GET /stream_filters` в момент создания — это
  устойчивее к различиям в именовании между версиями Keitaro.
* **Offer-поток** — использует паттерн Keitaro "прямая ссылка" (direct
  linking): `schema: landings` без лендингов и с одним оффером с долей
  100%, так что трафик редиректится прямо на URL, настроенный в самом
  оффере.
* **Откат (rollback)** — если какой-либо шаг создания завершается
  ошибкой (например, создание потока), ранее созданные в этой попытке
  сущности Keitaro (кампания/источник/группа) удаляются/архивируются по
  принципу best-effort.
* **Валидация** — ID оффера проверяется через `GET /offers/{id}` перед
  началом создания, поэтому неверный ID быстро возвращает понятную
  ошибку, а не оставляет после себя сломанную кампанию.

## Структура проекта

```
app/
  main.py                 FastAPI-приложение, подключает статический фронтенд
  config.py               Настройки (переменные окружения)
  database.py             SQLAlchemy engine/session
  models.py               ORM-модели (история кампаний, локальные потоки и офферы)
  schemas.py               Pydantic-схемы запросов/ответов
  keitaro_client.py        Тонкий асинхронный клиент Keitaro Admin API
  services/campaign_creator.py   Оркестрирует процесс создания кампании
  services/campaign_editor.py    Логика редактора: fetch/add/remove/pin/push офферов
  routers/campaigns.py     HTTP-эндпоинты создания и истории кампаний
  routers/campaign_editor.py     HTTP-эндпоинты редактора кампании
alembic/                  Миграции собственной БД приложения
static/                   HTML/JS-фронтенд (index.html — создание, editor.html — редактор)
```
